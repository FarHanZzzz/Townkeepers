# Nielsen's 10 Usability Heuristics — Manual Checklist

Use this checklist for qualitative UI review. Pair it with automated Lighthouse/axe results for coverage.

| # | Heuristic | What to check | Status | Notes |
|---|-----------|---------------|--------|-------|
| 1 | **Visibility of system status** | Users get timely feedback (loading, save success, errors, current location, selected state). | ☐ | |
| 2 | **Match between system and real world** | Labels, icons, and flows use familiar language; information appears in natural order. | ☐ | |
| 3 | **User control and freedom** | Users can cancel/undo/exit; clear back navigation; no trapped states. | ☐ | |
| 4 | **Consistency and standards** | UI patterns, terminology, button styles, and behavior are consistent across pages. | ☐ | |
| 5 | **Error prevention** | Confirm destructive actions; validate inputs; prevent invalid states before submission. | ☐ | |
| 6 | **Recognition rather than recall** | Options, labels, and instructions are visible; users shouldn't need to remember info across screens. | ☐ | |
| 7 | **Flexibility and efficiency of use** | Shortcuts/efficient paths for expert users; common tasks are easy. | ☐ | |
| 8 | **Aesthetic and minimalist design** | No irrelevant/noisy information; visual hierarchy supports the task. | ☐ | |
| 9 | **Help users recognize, diagnose, and recover from errors** | Error messages are clear, human, specific, and suggest a fix. | ☐ | |
| 10 | **Help and documentation** | Help is available when needed; instructions are concise and task-focused. | ☐ | |

## Suggested evidence
- Screenshot per issue
- Page/route and persona
- Severity (0-4): 0=not a problem, 1=cosmetic, 2=minor, 3=major, 4=catastrophic
- Recommended fix
